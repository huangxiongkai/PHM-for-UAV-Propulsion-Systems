# 无人机智能动力系统健康管理（PHM）与主动防护系统（Safety Copilot）技术报告

**版本：V3.5**


**项目角色：嵌入式系统架构与核心算法开发**

---

## 📜 摘要

在工业巡检、特种物流及高负载无人机作业场景中，动力系统瞬态突变（如大电流压降、电调/电机异常热累积）极易引发坠机灾难。传统飞控依赖标量绝对阈值报警，存在"响应滞后、只报不防"的缺陷，且极易在高机动打杆时因合法压降引发"报警风暴"。

针对上述工程痛点，本项目设计并实现了一套独立于主飞控的动力系统安全副驾驶模块（Safety Copilot）。系统严格对齐 PHM（故障预测与健康管理）Society 标准分层架构，基于 **RT-Thread Nano** 实时操作系统构建 5 线程管线流水线，在硬件端利用 ADC DMA 双缓冲猝发过采样消除电调 24kHz 高频混叠噪声；在特征提取层，创造性地引入带双阈值迟滞（Hysteresis）的油门冰冻（Throttle Freeze）机制与双时间尺度压降模型，并辅以斜率硬限幅（Slew Limit）离散微分算子，精准估计动力系统退化状态。

决策层采用**表驱动有限状态机（Table-Driven FSM）**与**并发硬故障位图（Bitmask）锁存**架构，通过 RT-Thread 事件集实现零延迟边沿唤醒；执行层采用**四层策略表驱动架构**，实现告警到物理动作的幂等分发与 Supervisor 失联自主检测。系统还配套了**编译时零开销 Testbench 故障注入框架**，支持 6 种故障类型注入与 CSV 日志输出。

实验表明，本系统能有效屏蔽大油门误报，在恶化初期提前 ______ 预警，硬实时任务响应延迟 < ______ ，显著提升了中小型无人机在复杂工况下的动力生存概率与容错裕度。

## 1. 项目定位与系统能力边界

基于对真实无人机坠机案例与硬件物理特性的深度剖析，系统将定位精准聚焦于边缘计算平台的"轻量级状态估计与动态健康管理（PHM）"。

### 1.1 系统能力声明与学术边界

受限于外挂式模块仅部署总电压与外壳 NTC 温度双传感器，本系统秉持工程求实与学术严谨精神，明确界定其能力边界：

**系统可准确评估（能做到）**：电池老化或低温引起的动力电池动态内阻增大趋势（通过 $DropRatio$ 估计）、整机高负载下的瞬态异常压降退化、电机/电调冷却失效引起的异常温升斜率。

**物理局限边界（无法做到）**：由于缺乏多路节点采集与电化学阻抗谱数据，系统无法实现单体电芯不平衡（Cell Imbalance）检测、无法提前捕获内部微短路（Internal Short Circuit）、无法推演绝对剩余寿命（RUL）。本系统定位于瞬态工况调理与即时主动防护，不适用于需要完整电化学建模的载人航天器。

### 1.2 真实工况映射与传统监控对比

| 故障/干扰类型 | 物理表现 | 传统监控缺陷 | 本系统（V3.5）解决方案 |
|:---|:---|:---|:---|
| 电调高频纹波 | 约 24kHz 开关噪声耦合至低频采样链路 | 频率混叠（Aliasing）导致误判跳变，引发"报警风暴" | DMA 双缓冲 64 次极速猝发均值滤波 + 去极值滤波 |
| 高机动瞬态压降 | 满杆爬升时，大电流导致电池内阻合法压降跌落 | 触发低压绝对警报，导致误报、频繁降级或迫降 | 引入 Throttle Freeze 双阈值迟滞机制，大油门期间冰冻稳态基准，完美隔离合法压降 |
| 缓慢热累积 | 负载过大或冷却失效导致电机/电调外壳温度缓升 | 超越绝对阈值时通常已造成退磁等不可逆损伤 | 提取 $\frac{dT}{dt}$ 离散微分特征，配合 Slew Limit 掐断噪声，实现斜率异常提前预警 |
| 极端恶性故障 | 单电芯突发短路、恶性超温或传感器物理死锁 | 单一标量故障标志位极易在嵌套判定中被级联覆盖丢失 | 采用**并发硬故障位图（Bitmask）+ 故障锁存**架构，多维硬故障无损直通熔断，需重启方可清除 |
| Supervisor 线程卡死 | 决策层线程因栈溢出或死锁停止心跳刷新 | 传统方案无独立看门狗，执行层继续按旧状态盲目动作 | Actuator 层内置 **Supervisor 心跳监测**，500ms 超时即切换蓝灯+长鸣独立告警 |

## 2. 系统总体架构（基于 PHM 范式）

系统架构严格对齐 PHM Society 推荐的标准分层结构，物理与逻辑均与主飞控隔离，符合航空电子"故障安全（Fail-Safe）"设计规范。系统基于 **RT-Thread Nano** 实时操作系统构建，采用优先级抢占与事件集同步机制。

### 2.2 IPC 对象总览

| 对象 | 类型 | 创建位置 | 用途 |
|:---|:---|:---|:---|
| `monitor_mq` | MessageQueue | mid_databus.c | Acquire→Predict 数据流，512B 静态池，单消费者 |
| `alarm_sem` | Semaphore | mid_databus.c | DMA ISR → Acquire 线程唤醒通知 |
| `predict_ready_sem` | Semaphore | mid_databus.c | Predict 首次写入 → Supervisor 冷启动同步（500ms 超时） |
| `adc_event` | Event | mid_databus.c | Supervisor → Actuator 边沿事件（SAFE/WARNING/DANGER/HARDFAULT） |
| `sensor_mutex` | Mutex (指针) | app_acquire.c | 保护 `monitor_msg` 全局共享结构体，优先级继承 |

### 2.3 架构核心优势

**高内聚低耦合**：Predict 层纯粹输出"客观退化风险点数"，Supervisor 层进行"状态决策与评估"，Actuator 层专职"安全闭环控制"，彻底解除了传统"if-else 阈值嵌套"带来的代码腐化，保障了硬实时响应。

**全线程自动初始化**：所有线程通过 `INIT_APP_EXPORT` 宏实现系统启动自动注册，无需手动调用初始化函数，避免遗漏初始化顺序。

**混合内存分配策略**：Acquire 线程采用静态初始化（`rt_thread_init` + 全局栈数组），MQ 和 Event 采用静态初始化（`rt_mq_init`、`rt_event_init`）；其余线程和部分 IPC（Semaphore、Mutex）采用动态创建（`rt_thread_create`、`rt_sem_create`、`rt_mutex_create`）。关键高频路径（Acquire）优先使用静态分配以确保确定性，其余模块在启动阶段动态创建，运行时无 `rt_malloc` 调用。

## 3. 数据采集与底层防御性设计

### 3.1 DMA 双缓冲与影子缓冲区架构

系统在硬件层采用 **DMA Circular 双缓冲 + 影子缓冲区** 模式，彻底解决 DMA 硬件写入与 CPU 读取的竞态问题：

- **物理缓冲区** `adc_raw_buf[256]`：DMA 硬件循环写入，CPU 不得直接读取
- **影子缓冲区** `adc_shadow_buf[256]`：ISR 中 `memcpy` 冻结，CPU 安全读取
- **半区就绪标志** `shadow_ready_half`：标识当前就绪的半区（0/1）

DMA 半传输完成回调（`HAL_ADC_ConvHalfCpltCallback`）冻结前半区 128 元素；全传输完成回调（`HAL_ADC_ConvCpltCallback`）冻结后半区 128 元素。两次回调均仅执行 `memcpy` + 置标志 + `rt_sem_release`，**ISR 内零阻塞操作**。

**采样参数**：TIM3 触发 ADC，2 通道（电压+温度）× 64 次采样 = 128 元素/半区，等效采样率约 12.658kHz，每次半区传输耗时约 5ms（200Hz 调度节拍）。

### 3.2 双重底层防御

针对电调产生的 24kHz 强纹波与潜在的硬件失效风险，系统在 Acquire_Thread 实施双重硬核防御：

**第一重 — 去极值均值滤波**（`fast_filing`）：对 64 次猝发采样值去除最大值与最小值后求算术平均，利用统计方法消除残余毛刺，信噪比提升约 12dB。

**第二重 — 原始码级传感器开路/短路检测**：在物理量转换之前，直接监控 ADC 原始寄存器码值。若电压通道码值 `v_avg ≤ 10`（接近短路）或 `v_avg ≥ 4085`（接近开路），直接置位 `sensor_fault = 3`，拒绝数据解算。

### 3.3 冷启动与初值强对齐保护

在离散计算领域，系统上电首帧的历史变量（如稳态基准 $V_{ref}$、平滑温度 $T_{smooth}$）均为零。若直接执行差分或微分计算，在开机瞬间会产生高达 $\frac{24\text{V} - 0\text{V}}{5\text{ms}}$ 的瞬态虚拟极大脉冲，从而引发错误的 DANGER 级误降级。

Predict 线程建立了冷启动保护防御机制：设置 `first_frame` 标志位，首帧运行时强制将当前采集到的物理原始值直接写入所有滑动窗口数组、快速时间尺度 $V_{fast}$、慢速稳态基准 $V_{ref}$ 以及平滑历史值中。通过在首帧切断离散数值的阶跃突变，彻底消灭了冷启动引起的开机误报。

Supervisor 线程同样具备冷启动同步机制：通过 `predict_ready_sem` 信号量等待 Predict 完成首次数据写入（500ms 超时），超时则锁存 `FAULT_PREDICT_INIT` 故障，确保不会在数据未就绪时执行误判。

### 3.4 参数集中配置化规范

为拒绝代码中散落的魔术字（Magic Numbers），系统构建了全局只读结构体 `predict_param_t`，将 **19 个关键参数** 进行集中统一管理，实现"一处配置，全局生效"：


## 4. 核心算法：健康特征提取与退化状态估计（Predict 7 阶段管线）

Predict 线程（`Logic_thread3`）采用严格的 **7 阶段管线架构**，每帧数据按顺序流经 7 个处理阶段，各阶段职责单一、数据流向清晰：

### 管线总览

```
MQ接收 → [Stage 1] 冷启动保护
        → [Stage 2] 传感器健康自检（范围检查 + ADC卡死检测）
        → [Stage 3] 滑动窗口 + Median3 去极值
        → [Stage 4] 温度特征提取链（IIR → 硬故障检测 → 微分 → SlewLimit → 二次IIR → 风险贡献）
        → [Stage 5] 电压特征提取链（快尺度IIR → 硬故障检测 → 微分 → SlewLimit → 油门迟滞冻结 → 慢尺度IIR → 压降比 → 风险贡献）
        → [Stage 6] 加锁写回全局数据总线
        → [Stage 7] predict_ready_sem 首次释放
```

### 4.1 Stage 1 — 冷启动保护

首帧标志位 `first_frame = 1` 时，将所有滤波器状态变量（滑动窗口、IIR 状态、$V_{fast}$、$V_{ref}$）强制初始化为当前采集值，切断零值阶跃突变。

### 4.2 Stage 2 — 传感器健康自检

**范围检查**：温度超出 $[-40℃, 150℃]$ 或电压超出 $[14.0V, 27.0V]$ 时，置位 `sensor_fault = 1`。

**ADC 卡死检测**：若电压与温度的原始值与历史平滑值之差均在极小阈值内（$|dV| < 0.0001V$ 且 $|dT| < 0.001℃$），累加静止计数器 `stuck_cnt`。连续 10000 帧（约 50 秒）无变化则判定 ADC 硬件死锁，置位 `sensor_fault = 2`。阈值从 V3.2 的 1000 提升至 10000，避免悬停稳态场景误触发。

### 4.3 Stage 3 — 滑动窗口 + Median3

维护 3 帧滑动窗口 `t_win[3]` / `v_win[3]`，通过三点真中值滤波器（`median3`）去除偶发单点毛刺。仅需 3 次比较操作，约 15 个时钟周期（72MHz 下约 0.2μs）。

### 4.4 Stage 4 — 温度特征提取链

```
Median3输出 → 一次IIR平滑(α=0.08) → 硬故障检测(>105℃)
            → 离散微分(dt/5ms) → SlewLimit(±10℃/s) → 二次IIR(α=0.06)
            → 风险贡献: 变化率风险 + 绝对温度风险, 上限50
```

**温度硬故障**：平滑温度 $T_{smooth} > 105℃$ 时，`hard_fault |= 0x01`。

**微分调理**：原始微分 $\frac{dT}{dt}$ 经 Slew Limit 钳位至 $\pm 10℃/s$，硬性截断 EMI 尖峰放大，再经二次一阶 IIR 低通滤波。

**温度风险贡献（双维度叠加）**：

| 维度 | 公式 | 含义 |
|------|------|------|
| 变化率风险 | $\max(0, dt_{final} - 1.2) \times 2.0$ | 温升速率超过 1.2℃/s 后线性增长 |
| 绝对温度风险 | $\max(0, T_{smooth} - 60) \times 0.5$ | 温度超过 60℃ 后叠加，弥补纯变化率在慢速升温场景下的盲区 |

两项之和经 `risk_cap=50` 钳位后写入 `temp_risk_contrib`，供 Supervisor 层 HI 计算使用。

### 4.5 Stage 5 — 电压特征提取链（双时间尺度 + 油门迟滞冻结）

系统维护两个不同记忆深度的动力学时间尺度模型：

- **$V_{fast}$（快速尺度）**：紧随当前 5ms 的真实负载瞬态，$\alpha = 0.15$
- **$V_{ref}$（慢速基准）**：代表电池在当前 SOC 下的稳态电动势，更新系数 $\gamma$ 由油门冻结逻辑动态控制

**油门双阈值迟滞冻结机制**：

遥控器摇杆物理电位器存在不可避免的噪声抖动，若仅采用单阈值判定，信号在阈值附近高频跳变会导致冰冻计时器频繁清零。本系统引入双阈值迟滞逻辑：

| 条件 | 行为 | $\gamma$ 值 |
|:---|:---|:---|
| 油门 > 1700（进入冰冻） | 启动冻结计时器 | $0.0$（彻底锁死） |
| 冻结持续 > 5 秒 | 切换为微弱跟踪 | $0.0002$（缓释跟踪） |
| 油门 < 1600（退出冰冻） | 计时器清零，恢复空闲 | $0.003$（标准空闲演化） |

**归一化压降比**：

$$DropRatio = \text{clamp}\left(\frac{V_{ref} - V_{fast}}{V_{ref}},\ 0.0,\ 1.0\right)$$

**电压硬故障**：$V_{fast} < 16.0V$ 时，`hard_fault |= 0x02`。

**电压风险贡献**：$DropRatio > 8\%$ 后线性输出，上限 50。

### 4.6 Stage 6 — 加锁写回全局数据总线

通过 `sensor_mutex` 互斥量保护，将 11 个字段原子写入 `monitor_msg` 全局结构体，同时记录 `timestamp = rt_tick_get()` 作为 Predict 线程心跳。

### 4.7 Stage 7 — 冷启动同步信号

首次写回完成后释放 `predict_ready_sem`，通知 Supervisor 线程可以开始首帧定态计算。

## 5. 状态机决策与主动防护闭环（Supervisor 9 层管线）

Supervisor 线程以 **20ms 周期（50Hz）** 运行，采用严格的 **9 层管线架构**，每层职责独立、数据单向流动：

### 管线总览

```
Layer 1: 互斥量快照      → 冻结 monitor_msg 到局部副本
Layer 2: 冷启动首帧定态  → 根据首帧HI直接判定初始状态
Layer 3: HI计算          → 综合健康指数 = 100 - TempRisk - DropRisk
Layer 4: 条件保持        → 持续帧计数器，防止噪声瞬态触发
Layer 5: 表驱动FSM       → 4条转换规则，Flash只读常量表
Layer 6: 故障锁存        → 最先触发故障永久记录，需重启清除
Layer 7: 告警融合        → 锁存故障 > FSM状态，输出最终告警等级
Layer 8: 边沿事件发布    → 仅状态变化时发送事件集，零冗余唤醒
Layer 9: 看门狗预留      → 未来扩展 acquire/predict 心跳监测
```

### 5.1 Layer 2 — 冷启动首帧定态

系统上电后，Supervisor 首先通过 `predict_ready_sem` 等待 Predict 完成首次数据写入（500ms 超时）。首帧根据 HI 值直接判定初始状态：

- $HI < 40$：直接定态 DANGER
- $HI < 80$：直接定态 WARNING
- $HI \geq 80$：定态 SAFE

若等待超时，锁存 `FAULT_PREDICT_INIT` 故障，首帧直接上报 HARDFAULT。

### 5.2 Layer 3 — 综合健康指数（HI）计算

$$HI = \text{clamp}(100 - TempRisk - DropRisk,\ 0,\ 100)$$

内部采用放大 10 倍的整数运算（`hi_x10`，范围 0~1000），避免浮点比较的精度问题。

### 5.3 Layer 4+5 — 条件保持 + 表驱动 FSM

传统 if-else 嵌套状态机极易在条件复杂化时产生逻辑漏洞。本系统创新性地将 FSM 转换规则抽象为 **Flash 只读常量表** `g_rules[]`，运行时通过遍历匹配实现状态转移：

```c
static const transition_rule_t g_rules[] = {
    /* 当前状态      目标状态     HI阈值(×10)  持续帧数  比较类型 */
    { SAFE,    WARNING,  800,  10, CMP_BELOW },  /* HI<80, 持续200ms */
    { WARNING, DANGER,   400,   5, CMP_BELOW },  /* HI<40, 持续100ms */
    { WARNING, SAFE,     840,  50, CMP_ABOVE },  /* HI>84, 持续1000ms */
    { DANGER,  WARNING,  450,  25, CMP_ABOVE },  /* HI>45, 持续500ms */
};
```

**条件保持机制**：条件必须持续满足指定帧数（`hold_frames`）才执行转移，防止噪声引起的瞬态误切换。新目标出现时重置计数器，确保状态转移的确定性。

**滞回死区设计**：

| 转移方向 | 阈值 | 持续要求 | 等效死区 |
|:---|:---|:---|:---|
| SAFE → WARNING | HI < 80 | 200ms | 恢复需 HI > 84（+4 点裕量） |
| WARNING → DANGER | HI < 40 | 100ms | 恢复需 HI > 45（+5 点裕量） |

### 5.4 Layer 6 — 故障锁存

当检测到以下任一恶性条件时，`fault_latched` 永久置位，记录最先触发原因 `fault_cause`，**需重启方可清除**：

| 触发条件 | 故障原因 | fault_cause 枚举值 |
|:---|:---|:---|
| `sensor_fault ≠ 0` | 传感器故障 | `FAULT_SENSOR (3)` |
| `hard_fault & 0x01` | 严重过温 | `FAULT_OVERTEMP (4)` |
| `hard_fault & 0x02` | 严重欠压 | `FAULT_UNDERVOLT (5)` |
| `timestamp` 陈旧 > 200ms | Predict 线程卡死 | `FAULT_PREDICT_LOST (2)` |
| `predict_ready_sem` 等待超时 | Predict 启动失败 | `FAULT_PREDICT_INIT (1)` |

### 5.5 Layer 8 — 边沿事件发布

仅当 `final_alarm ≠ last_alarm` 时（即状态发生跃迁），才通过 `rt_event_send` 向事件集 `adc_event` 发送对应位：

```c
#define EVT_SAFE      (1 << 0)
#define EVT_WARNING   (1 << 1)
#define EVT_DANGER    (1 << 2)
#define EVT_HARDFAULT (1 << 3)
```

Actuator 线程通过 `rt_event_recv` 阻塞等待，**零轮询开销**，事件到达瞬间唤醒。

## 6. 执行层：Actuator 四层架构

Actuator 线程采用**四层分层架构**，实现从告警事件到物理动作的清晰映射：

### 6.1 架构总览

```
L1: 事件接收层    → rt_event_recv 阻塞等待 + Supervisor心跳监测
L2: 策略查表层    → resolve_policy() 静态只读策略表
L3: 幂等分发层    → dispatch_plan() 状态变化时才刷新硬件
L4: 驱动适配层    → drv_led_write() / drv_beep_freq() 硬件抽象
```

### 6.2 L1 — 事件接收 + Supervisor 失联检测

Actuator 以 **500ms 超时**（非永久阻塞）等待 `adc_event` 事件集。无论是否收到事件，都会读取 `monitor_msg.supervisor_heartbeat` 判断 Supervisor 是否失联：

```c
supervisor_lost = ((rt_tick_get() - local.supervisor_heartbeat) > SUPERVISOR_TIMEOUT_TICKS);
```

若 Supervisor 心跳陈旧超过 500ms，判定为失联，Actuator 自主切换至独立告警模式。

### 6.3 L2 — 静态只读策略表

5 种告警等级对应 5 套执行计划（`action_plan_t`），全部以 `const` 常量存储在 Flash 中：

| 策略索引 | 告警等级 | LED 行为 | 蜂鸣器行为 |
|:---|:---|:---|:---|
| POLICY_SAFE | SAFE | 纯绿常亮 | 静音 |
| POLICY_WARNING | WARNING | 红+绿闪烁（500ms，黄光） | 3kHz 单次滴答，2s 间隔 |
| POLICY_DANGER | DANGER | 纯红快闪（100ms） | 3kHz 双响组，1s 间隔 |
| POLICY_HARDFAULT | HARDFAULT | 纯红快闪（100ms） | 4kHz 连续急响 |
| POLICY_SUPERVISOR_LOST | Supervisor失联 | 纯蓝常亮 | 4kHz 持续长鸣 |

### 6.4 L3 — 幂等分发

`dispatch_plan()` 通过 `rt_memcmp` 比较新旧策略，**完全相同则跳过**，避免重复操作定时器。状态变化时先停止定时器、再写入新计划、最后启动对应硬件，防止回调读取半成品数据。

### 6.5 L4 — 驱动适配

- **LED 驱动**：`drv_led_write(r, g, b)` 封装 GPIO 操作，内部处理 active-low 反转（`GPIO_PIN_RESET` = 点亮），上层只操作布尔值
- **蜂鸣器驱动**：`drv_beep_freq(freq)` 封装 PWM 参数计算与 TIM2_CH4 输出，0Hz 自动停止

### 6.6 定时器状态机

LED 使用 **周期定时器**（`RT_TIMER_FLAG_PERIODIC`）实现闪烁；蜂鸣器使用 **单次定时器**（`RT_TIMER_FLAG_ONE_SHOT`）+ 回调内动态重配时间，实现三相位状态机（鸣响 → 组内间隔 → 组间间隔）。

## 7. Testbench 故障注入框架

### 7.1 设计哲学

为在不污染主干算法源码的前提下验证系统的鲁棒性，系统设计了**编译时零开销**的 Testbench 故障注入框架。通过 `tb.h` 中的 `USE_TESTBENCH` 宏开关，Release 版本注释该行即可**完全剔除**所有测试代码，零 Flash/RAM 开销。

### 7.2 架构设计

Testbench 在 Acquire 线程的数据流路径中插入**劫持点**：

```
DMA影子缓冲 → fast_filing → [tb_read_volt_raw / tb_read_temp_raw 劫持点]
                           → Pot_To_SimBatteryVol / calculate_temp
                           → monitor_msg
```

当 Testbench 激活时，劫持函数替换真实 ADC 码值为仿真物理模型输出；未激活时直接透传原始值，编译器优化为零开销。

### 7.3 支持的功能

**飞行阶段仿真**：

```c
typedef enum {
    PHASE_IDLE    = 0,  /* 地面静置 */
    PHASE_TAKEOFF = 1,  /* 起飞大负载 */
    PHASE_HOVER   = 2,  /* 悬停稳态 */
    PHASE_CRUISE  = 3,  /* 巡航 */
    PHASE_LAND    = 4   /* 降落 */
} TB_Phase;
```

**6 种故障类型注入**：

| 故障枚举 | 物理含义 | 注入方式 |
|:---|:---|:---|
| `TB_FAULT_VOLT_FAST_DROP` | 快速掉压（5V/s） | 电压码值斜坡递减 |
| `TB_FAULT_TEMP_FAST_RISE` | 快速升温（3℃/s） | 温度码值斜坡递增 |
| `TB_FAULT_ADC_STUCK` | ADC 卡死 | 返回固定码值 |
| `TB_FAULT_NTC_OPEN` | NTC 开路 | 返回极端码值（≥4090） |
| `TB_FAULT_VOLT_UNDERVOLT` | 直接强制欠压 | 电压码值强制拉低 |
| `TB_FAULT_TEMP_OVERTEMP` | 直接强制过温 | 温度码值强制拉高 |

**CSV 日志输出**：`tb_log_csv()` 将每帧的仿真时间、物理状态、告警等级、故障原因格式化为 CSV 行输出至串口，便于后续 Python/MATLAB 离线分析。

**实验元数据**：通过 `TB_ExperimentInfo` 结构体记录实验编号、场景编号、故障类型、故障起始时间，支持自动化批量测试管理。

## 8. 数据总线与共享结构体

### 8.1 monitor_msg_t — 13 字段监控消息

```c
typedef struct {
    float temperature;       /* 滤波后温度 (℃) */
    float voltage;           /* 滤波后电压 (V) */
    float dt_tem;            /* 温度微分 (℃/s) */
    float dv_vol;            /* 电压微分 (V/s) */
    float drop_ratio;        /* 归一化压降比 [0,1] */
    float temp_risk_contrib; /* 温度风险贡献 [0,50] */
    float drop_risk_contrib; /* 压降风险贡献 [0,50] */
    uint8_t alarm_level;     /* 0=SAFE, 1=WARNING, 2=DANGER, 3=HARDFAULT */
    uint8_t hard_fault;      /* 位图: bit0=过温, bit1=欠压 */
    uint8_t sensor_fault;    /* 0=正常, 1=范围越限, 2=ADC卡死, 3=传感器开路/短路 */
    rt_tick_t timestamp;     /* Predict线程心跳时间戳 */
    rt_tick_t supervisor_heartbeat; /* Supervisor线程心跳时间戳 */
    uint8_t fault_cause;     /* 故障原因枚举值 */
} monitor_msg_t;
```

**V3.5 新增字段**（相比 V3.2）：
- `supervisor_heartbeat`：Supervisor 线程每 20ms 刷新，供 Actuator 判断失联
- `fault_cause`：记录最先触发的故障原因枚举，支持故障溯源
- `timestamp`：Predict 线程写回时刻，Supervisor 用于检测 Predict 卡死（200ms 超时）

### 8.2 互斥量保护策略

所有对 `monitor_msg` 的读写操作均通过 `sensor_mutex` 互斥量保护：
- **写入方**（Acquire、Predict、Supervisor）：`rt_mutex_take` → 修改字段 → `rt_mutex_release`
- **读取方**（Display、Actuator）：`rt_mutex_take` → `memcpy` 到局部副本 → `rt_mutex_release` → 在锁外使用副本计算

## 10. 结论与后续演进规划（V4.0）

本系统（V3.5）在 V3.2 基础上完成了从"单线程特征提取"到"五线程 PHM 管线流水线"的全面架构升级：

1. **Predict 7 阶段管线化**：冷启动保护→传感器自检→Median3→温度链→电压链→油门迟滞→加锁写回，每阶段职责单一，数据流向清晰可追溯。

2. **Supervisor 9 层管线**：引入表驱动 FSM、条件保持防抖、故障锁存、边沿事件发布等工业级决策机制，通过 `predict_ready_sem` 实现跨线程冷启动同步。

3. **Actuator 四层架构**：策略表驱动 + 幂等分发 + 定时器状态机 + Supervisor 失联自主检测，实现告警到物理动作的完全解耦。

4. **Testbench 故障注入框架**：编译时零开销、6 种故障类型、CSV 日志输出，支持自动化批量回归测试。

5. **19 参数集中配置化**：`predict_param_t` 消除全部魔术字，参数调优只需修改一处。

6. **monitor_msg 扩展**：新增心跳、时间戳、故障原因字段，支持失联检测与故障溯源。

未来，系统将沿着全数字化动力链方向继续向 V4.0 全飞行包络耦合阶段演进：

- **电流维度的全面补全**：引入 INA226 电流监测模块，实时解算绝对动态内阻 $R_{internal} = \frac{\Delta V}{\Delta I}$。
- **分布式多电芯监测**：接入 Smart Battery 的 CAN/SMBus 协议栈，实现单体电芯失衡检测。
- **SBUS 串联拦截**：Actuator 层增加 SBUS 协议解析与重映射，实现油门限幅与保姿态降级。
