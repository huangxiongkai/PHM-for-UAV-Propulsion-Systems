## 1. 总体结论

### ⚠️ FAIL（PHM 提前预警能力失效）

系统能正确检测过温（HARDFAULT），但** FSM 未产生 WARNING/DANGER 中间态**，PHM 的核心价值——提前预警——在慢速升温场景下完全失效。

| 指标 | 预期 | 实测 | 判定 |
|------|------|------|------|
| HARDFAULT 触发 | ≤120°C | 105.3°C（硬编码阈值） | ✅ |
| 状态转移链 | SAFE→WARNING→DANGER→HARDFAULT | SAFE→**直接 HARDFAULT** | ❌ |
| Early Warning 提前量 | > 0 | **0s**（无 WARNING） | ❌ |
| 过温告警响应时间 | < 1ms | 142µs | ✅ |
| 堆栈安全 | < 50% | 最高 47% | ✅ |

**核心发现**：在 3°C/s 慢速升温场景下，TRisk 始终稳定在 ~3.6，HI ≈ 96.4，FSM 永远停在 SAFE，直到 t=28.3s 温度超过 105°C 才被过温硬故障阈值直接判定为 HARDFAULT。

**→ 直接导出修复工作（EXP-04）**：新增 `temp_abs_threshold` + `temp_abs_slope` 双通道计算，修复后 Early Warning 提前量达到 **3.7s**。

## 4. 根因分析

### 4.1 TRisk 计算逻辑（PRE-fix 版本）

**`app_predict.c:177-181`（PRE-fix 代码）**：

```c
/* 4d. 温度风险贡献 */
float temp_risk_raw = 0.0f;
if (dt_final > P.temp_risk_slope)           // dt_final ≈ 2.69~3.0°C/s
    temp_risk_raw = (dt_final - 1.2) * K_TEMP;  // = 1.5 × 2 = 3.0 ~ 1.8 × 2 = 3.6
float final_temp_risk = float_clamp(temp_risk_raw, 0.0f, P.risk_cap);
```

### 4.2 数学计算

在 +3°C/s 注入下（滤波后有效速率 ~2.69°C/s），`dt_final` 稳态约 3.0°C/s：

```
变化率风险 = (3.0 - 1.2) × 2.0 = 3.6   （常数）
HI = 100 - 3.6 - 0.0 = 96.4
```

### 4.3 WARNING 触发条件分析

| FSM 转移 | 触发条件 | 实际 HI | 是否满足 |
|---------|---------|--------|---------|
| SAFE→WARNING | HI < 80 持续 200ms | 96.4 | ❌ 不满足 |
| WARNING→DANGER | HI < 40 持续 100ms | — | ❌ 永远不会到达 |

### 4.4 根因总结

**TRisk 仅依赖温度变化率 `dt_final`，不考虑绝对温度**：

- 无论温度是 35°C 还是 104°C，只要升温速率相同，TRisk 就相同
- 这是纯"变化率检测"而非"综合健康评估"
- 慢速、持续、长时间的温升（如冷却系统失效）被严重低估

## 5. 设计缺陷的本质

### 5.1 PHM 标准要求

PHM Society 标准对"退化早期检测"的基本要求：

> 退化状态估计应综合考虑 **速率变化** 与 **绝对水平**，在系统接近失效前给出预警。

### 5.2 PRE-fix 的设计盲区

**场景 1：急停/堵转（高变化率）**
- dt_final > 5°C/s
- TRisk > 7.6 → 能检测到

**场景 2：缓慢过温（低变化率、高绝对值）**
- dt_final ≈ 3°C/s（恒定）
- TRisk ≈ 3.6（恒定）→ **漏检** ❌

### 5.3 物理直觉对照

| 真实物理场景 | dt | t_smooth | 应有风险 | PRE-fix 输出 |
|-------------|-----|---------|---------|-------------|
| 电机正常运转短时发热 | 低 | 45°C | 低 | 低 ✅ |
| 急停/堵转瞬间 | **高** | 60°C | **高** | 高 ✅ |
| 冷却失效缓升 | 低 | **95°C** | **高** | 低 ❌ |
| 电机长期过载 | 中 | 85°C | 中高 | 中 ❌ |

## 8. 修复方案

### 8.1 修改目标

在 Stage 4d TRisk 计算中**叠加绝对温度通道**，使慢速升温在高温度下也能累积风险。

### 8.2 新增参数（`app_predict.h`）

```c
typedef struct {
    /* ... 现有字段 ... */
    float temp_risk_slope;      /* 1.2  温度变化率风险起始阈值 ℃/s */
    float temp_abs_threshold;   /* 60.0 绝对温度风险起始阈值 ℃（新增） */
    float temp_abs_slope;       /* 0.5  绝对温度风险斜率 risk/℃（新增） */
} predict_param_t;

static const predict_param_t P = {
    /* ... */
    .temp_risk_slope    = 1.2f,
    .temp_abs_threshold = 60.0f,
    .temp_abs_slope     = 0.5f,
};
```

### 8.3 新公式（`app_predict.c` Stage 4d）

```c
/* 4d. 温度风险贡献（变化率 + 绝对温度，双通道叠加） */
float temp_risk_raw = 0.0f;

/* 变化率风险（保留） */
if (dt_final > P.temp_risk_slope)
    temp_risk_raw += (dt_final - P.temp_risk_slope) * K_TEMP;

/* 绝对温度风险（新增） */
if (t_smooth > P.temp_abs_threshold)
    temp_risk_raw += (t_smooth - P.temp_abs_threshold) * P.temp_abs_slope;

float final_temp_risk = float_clamp(temp_risk_raw, 0.0f, P.risk_cap);
```

### 8.4 预期修复效果

| 温度 | 变化率项 | 绝对温度项 | TRisk 总 | HI | ALM |
|------|---------|-----------|---------|-----|-----|
| 60°C | 3.6 | 0.0 | 3.6 | 96.4 | SAFE |
| 80°C | 3.6 | 10.0 | 13.6 | 86.4 | SAFE |
| **95°C** | **3.6** | **17.5** | **21.1** | **78.9** | **⚠️ WARNING** |
| 105°C | 3.8 | 22.5 | 26.3 | 73.7 | 🔴 HARDFAULT |

**预期 Early Warning 提前量**：约 3.3s（基于 95°C vs 105°C 的温差、3°C/s 注入速率）。

## 10. 经验总结

### 10.1 PHM 公式设计的两条腿

- **变化率检测**：捕捉瞬间冲击，灵敏度高但持续时间短
- **绝对水平检测**：捕捉慢性退化，对慢速、长时间累积敏感

**单一维度的风险指标在复杂场景中必然失效**。

### 10.2 Testbench 的价值

Testbench 框架让这类算法缺陷可以在**不损坏真实硬件**的前提下被快速发现：
- 故障注入时间精确可控（5.0s 起始）
- CSV 日志便于离线分析每帧数据
- 场景模型模拟真实飞行阶段（起飞/悬停/巡航/降落）
